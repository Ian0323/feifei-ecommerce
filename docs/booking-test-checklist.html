非非768 預約系統 — 測試清單

請依以下項目逐一測試，於空白方框打勾。如遇問題請截圖回報。

一、測試裝置（建議至少各一台）

  • iPhone（用 LINE 內建瀏覽器開）
  • iPhone（用 Safari 開）
  • Android 手機（用 LINE 內建瀏覽器開）
  • Android 手機（用 Chrome 開）
  • 電腦桌機（Chrome / Edge）

二、入口連結（兩個都要測）

  • LIFF 連結：https://liff.line.me/2009821980-46y6BEMh
  • 直連網址：https://myfeifei768.com.tw/booking.html?plan=single
兩個入口都必須直接顯示 NT$3,800 單次問事，不可先進入方案選擇頁。一般瀏覽器送出時會導向 LINE Login，回跳後應恢復表單。

三、頁面開啟檢查

  • 頁面能正常顯示，沒有破版、亂碼、跑版
  • 最上方顯示「目前開放方案」與「目前僅開放單次問事」，沒有「更換方案」按鈕
  • 最上方有「預約須知」深藍色框 + 同意勾選框
  • 方案名稱固定為「單次問事」，所有金額都顯示 NT$3,800
  • 用舊網址 booking.html?plan=guidance 或 booking.html?plan=deep 開啟，仍只能顯示單次問事 NT$3,800
  • 直接開啟 membership.html 時可閱讀三方案介紹，但不會 LINE 登入、沒有選擇按鈕或推薦問答
  • 下方有日曆，今天日期是 5/X 時應顯示 5 月

四、預約須知與同意框

  • 沒勾選同意就點日期 → 跳出 alert「請先勾選『我已閱讀預約須知』」，且勾選框會閃高亮
  • 勾選後再點日期 → 順利進到時段選擇
  • 進到時段（步驟 2）後，預約須知整塊收起來不再顯示
  • 按「← 改日期」回到步驟 1，預約須知仍維持收起狀態（不會再跑出來）

五、日曆功能

  • 灰色（不可點）的日期：週六、週日
  • 顯示「滿」字樣的日期：當日時段全被預約（這項較難測，可略過）
  • 「← 上個月」按鈕 → 在當月開啟時應該是灰色不可點
  • 「下個月 →」按鈕 → 點擊可切到下個月
  • 每次切換步驟（1↔2↔3） → 不會跳回頁面最頂端，而是滑到該步驟區塊

六、時段選擇

  • 每個可預約日（週一～五）都顯示 5 個時段：10:30、11:30、14:30、15:30、16:30
  • 週二也一樣是這 5 個，沒有晚上的延長時段
  • 已被預約的時段：灰色不可點
  • 點「← 改日期」可回到日曆

七、填寫資料表單

各欄位逐一測試錯誤輸入會被擋下：

  • 手機號碼：填「12345」應跳「請輸入有效的手機號碼」
  • Email：填「abc」（無 @）應跳「請輸入有效的 Email」
  • 生年月日：
    • 只剩「民國」，不再有國曆切換選項
    • 年份 placeholder 顯示「民國年」
    • 三格都填正確（例：80 / 5 / 12）→ 通過
    • 任一格留空 → 應該擋下
  • IG 帳號：必填，留空擋下
  • LINE 顯示名稱：必填（從 LINE 開啟時應自動帶入，可手動改）
  • 詢問方向：
    • 可選「事業、財運、姻緣、學業、家庭、其他」，未選應擋下
    • 選「其他」→ 顯示文字欄位；未填內容應擋下
    • 進入確認頁後，應顯示所選方向；「其他」應顯示為「其他：填寫內容」
  • 諮詢方式：已無選項欄位，表單只顯示線上視訊的匯款資訊（不應出現「現場」或任何地址）
  • 匯款末五碼：必填，非 5 位數字應擋下
  • 匯款截圖勾選：
    • 不勾 → 按「確認預約資料」應跳提醒、頁面捲到勾選框並閃紫框
    • 勾了 → 才能進入確認頁

八、送出預約（既有流程）

  • 全部填正確 → 跳出確認資訊（可再次檢查）
  • 確認送出 → 顯示「預約成功」頁面，並顯示日期 + 時段
  • 成功頁應出現「📸 最後一步：傳匯款截圖」提醒區塊
  • 成功頁顯示預約編號（格式例：F768-260727-A1B2）
  • 成功頁有按鈕「前往官方 LINE 傳匯款截圖」
  • 馬上重新整理頁面 → 看時段是否變灰（代表後台已寫入）

九、LINE 好友情境（Booking v2）

  • 已登入 + 已是好友：送出按鈕維持「送出預約」，不跳額外 modal，直接送出
  • 已登入 + 不是好友：按鈕文案為「加入官方 LINE 並送出預約」；點擊後只出現 LINE 原生加好友提示
  • 接受加好友 → 自動繼續送出
  • 取消加好友 → 所有已填資料與 Step 4 都保留，可再按一次
  • LINE 顯示名稱仍自動帶入且可手動修改
  • Sheet 第 10 欄 LINE UID 應為後端驗證後的值（非空、以 U 開頭）
  • Sheet 第 19 欄「LINE 好友狀態」有記錄（已確認好友 / 未確認 等）
  • Sheet 第 20 欄「詢問方向」有記錄；選其他時格式為「其他：填寫內容」

十、一般瀏覽器 + LINE Login 草稿恢復

  • 未登入 LINE 時填完整表單後按送出 → 導向 LINE Login
  • Login 回跳後：日期、時段、所有欄位、checkbox 都恢復，不需重填
  • 預約成功後 draft 清除（重新整理不會再跳出舊資料）
  • sessionStorage 中沒有 ID token

十一、官方 LINE 傳截圖按鈕

  • 按鈕只開啟非非官方帳號（不會送到來源聊天室）
  • 固定訊息含：預約編號、日期、時段
  • 客戶不需重新輸入預約資料，接著選截圖送出即可
  • iOS LINE / Android LINE / Safari / Chrome 各測一次
若 CONFIG.OFFICIAL_LINE_CHAT_URL 仍為空，按鈕會提示「尚未設定」並嘗試複製訊息 — 此為已知 blocker，請業主補上官方 URL 後再驗正式站。

十二、Google Calendar 同步（助理後台）

  • 新預約自動建立一個「【待確認】姓名｜線上諮詢」事件，長度 60 分鐘
  • Sheet 第 17 欄寫入 Calendar Event ID
  • Sheet 改「已確認」→ 同一事件標題改為「【已確認】…」，不另建第二個
  • Sheet 改「已取消」→ 事件刪除，網站時段釋放
  • 公開時段 Sheet 沒有重複 block

十三、前一天提醒（助理後台）

  • 僅「已確認」且預約日為明天者會收到 LINE 提醒
  • 待確認 / 已取消 / 已完成 不提醒
  • 同一筆 Trigger 重跑只發一次（第 18 欄提醒時間有值）
  • 文案不含生日、備註、匯款末五碼
  • UID 空白或推播失敗時 Email 備援，第 18 欄記「Email備援 …」

十四、通知收件確認

  • 助理 Email 有收到新預約通知（含預約編號、詢問方向）
  • 客戶 LINE 有收到「已收到預約申請」推播（含詢問方向）
  • Sheet 改已確認 → 客戶 Email + LINE 確認通知
  • Sheet 改已取消 → 客戶 Email + LINE 取消通知

十五、錯誤情境

  • 同一個 Email 在 60 秒內連送兩次 → 第二次應被擋下
  • 故意把網路關掉再送出 → 應該顯示錯誤頁，可重試
  • LINE 未登入/驗證失敗 → 顯示需 LINE 登入，表單資料不應清空
